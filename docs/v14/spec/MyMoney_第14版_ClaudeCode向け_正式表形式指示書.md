# My Money 第14版｜3タブ再構成と旧機能の表形式移設指示書

更新日：2026-11-11  
対象：My Money / Today Money のホーム・支払い・その他（3タブ）および関連詳細画面。  
**これは実装指示書であり、実装完了報告ではない。**

## 最優先の決定事項

1. 旧5タブ（今日／給与／支払い／資産／設定）を**ホーム／支払い／その他**の3タブへ再編する。給与・資産は消さず、再設計した専用詳細画面へ移す。
2. ホーム上段は **今日の支出→総資産→今月の給与→ACF→直近の支払い** の順にカード表示。警告はある時だけ最上部。
3. 旧画面にある **カテゴリ別支出・取引履歴・日締め・比較分析・明細照合・計画** などは削除禁止。必要に応じて**3行までのコンパクトな表（iOS風グループリスト）**に変え、「すべて見る」で詳細画面を開く。
4. 入力は原則、右下固定の**小型＋ボタン**から集約。支出・臨時収入・銀行残高・給与の同じ入口を別の場所に重複配置しない。
5. 各カードは「カード見出しは外／左に数字／右に小型グラフ」。背景は不透明な白カード、Liquid Glassは操作レイヤー中心。
6. 遷移表はボタン表とは**別に管理**。遷移先と戻りの起点・状態保持を確認してから、旧入口を削除する。
7. 各シートの **設計IDはUI仕様の追跡用IDであり、HTML DOMに実在することを意味しない**。現行HTMLで確認できた例は `homeTab`、`tabbar`、`screen-today`、`screen-payments`、`screen-settings`、および設定画面の `categorySettings`、`tagSettings`、`dataSettings` 等。旧304台帳の DOM名称は、Claude Codeが最新コードと照合すること。

## 実装順序

**Phase A：現行コードを調査し、「設計ID → 実際のDOM要素・イベント・関数・ファイル」対応表を完成。** READMEのビルド方法と既存保存形式を守る。  
**Phase B：3タブ＋検索/プロフィール/＋の共通ナビを実装。**  
**Phase C：ホームカード5種とカテゴリ別支出等の表を実装。**  
**Phase D：支払いroot、その他root、給与・資産・ACF等の専用画面を再設計。**  
**Phase E：遷移と旧304操作の移設確認、保存/キャンセル/復元/削除の安全性テスト。**  
**Phase F：iPhone 15 Pro相当の画面でbefore/after実証。最初の画面の情報密度、押せる場所の認識、カード見た目、戻る・保存を検証。**

## 共通の実装・品質条件

| 項目 | 実装ルール |
|---|---|
| 表示密度 | 初期画面は支出カード＋総資産カード＋次カードの一部を目安。高さとDynamic Typeで可変、無理な固定高は避ける。 |
| 表示条件 | 警告カードは発生時だけ表示。ACF/給与/口座のデータがない時は、数字0や偽のグラフを出さず状態コピーと次の行動を示す。 |
| 色とマテリアル | コンテンツ：不透明白カード＋semantic grouped背景。Liquid Glass：タブバー・検索・プロフィール・＋ボタン・メニューなど操作層。 |
| 表の表示行数 | ホームのカテゴリ別支出・取引は原則3行まで。「すべて見る」から専用画面へ。 |
| 重複ボタン | 支出・臨時収入・残高更新・給与登録は＋ハブが唯一のトップ入力導線。同じ機能のホーム直下ボタンは設置禁止。 |
| カードタップ | 1枚全体が単一路線なら全面タップ。内部に別操作がある場合はタッチ領域を分離し誤遷移を防止。 |
| 長押し | ユーザーが期待できる項目でのみ補助操作。長押ししか道がない操作を作らない。 |
| スワイプ | 横の操作はセグメント・日付・詳細グラフ等の限定領域。画面全体の左右スワイプでrootを移動しない。 |
| ナビゲーション | ルートの階層を保持。給与と資産はホーム・その他の両方から入れても同じ専用画面。backは起点に正確に戻る。 |
| モーション | 通常220〜320ms、押下90〜120ms、ドラッグは指追従。prefers-reduced-motionに必ず対応。 |
| 紙めくり | ＋入力画面は右下起点の軽いページカール風。過剰な3D変形/文字の歪みは不可。Web環境で不安定なら連続拡大sheetにフォールバック。 |
| アクセシビリティ | タップ領域44pt目安。VoiceOverの名前、フォーカス移動、Dynamic Type、ダークモード、iOS Safariのsafe-areaを検証。 |
| 金融安全 | 予測・グラフ・ホイールの操作だけで残高・請求・給与を保存しない。保存/反映/削除は明示確認。 |
| 実装方式 | README記載のsrc/jsとsrc/cssの既存構造に統合し、継ぎ足しCSS禁止。変更後はnpm run build/npm testとbrowserテスト。 |
| 旧機能保護 | 第11版の304 IDと第13版の機能を全件照合し、表内「新しい移設先」を実コードで確定。移設前に旧入口を削除禁止。 |

## Claude Code 完了報告の必須列

`設計ID／現行HTML ID or 動的セレクタ／ソースファイルと関数／変更前画面／変更後画面／操作・遷移テスト／副作用テスト／コミットSHA／完了状態` を全件記録する。

以下が1つでも残っていれば「全面実装完了」と報告しない：旧304操作に新入口のないもの、保存時の二重反映、戻るで表示期間が消えるもの、カテゴリ表がトップで全件展開されている箇所、支払いリスク警告がグラフの下に埋もれる箇所、旧5タブの残骸、モーション低減対応漏れ。

### ビルド・検証

`npm ci` → `npm run build` → `npm test` → `npm run test:browser` を最低限実行。可能なら既存の `test:crawl`、`test:p0`、`test:scenarios` に対応する新ルートのケースを追加する。GitHub Pagesへの反映後は画面幅 393×852 ほか 320/430px、ライト・ダーク、文字サイズ拡大、VoiceOver相当の操作を確認する。*設定・認証・バックアップの実データを破壊しないテストデータを使用すること。*
