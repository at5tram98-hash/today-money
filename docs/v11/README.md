## CSSの再構成

版ごとに上書きを重ねていた16ファイル（`00-base.css`〜`workspace.css`、`v11-components.css`）を廃止し、部品ごとの16ファイルへ作り直しました。

| 項目 | 数 |
|---|---|
| 元の規則／セレクタ単位の項目 | 2,302／2,578 |
| どこからも使われていないクラスの規則を削除 | 174項目（85クラス。一覧は `css-restructure-stats.json`） |
| 後の規則に上書きされて効いていなかった宣言を削除 | 486 |
| 同じセレクタの規則を1つに統合 | 202 |
| 出力の規則数 | 2,028 |

方法（`scripts/v11/css-restructure.mjs`）：全規則をセレクタ単位に分解し、同じ要素・同じ優先度で競合しうる規則の組だけ元の前後関係を制約として保ちながら、統合と並べ替えを行いました。競合の判定には、巡回で観測した要素のクラスの組と、スクリプト中の class 属性の記述を使っています。

検証：旧ビルドと新ビルドに同じ操作を行い、全要素（疑似要素を含む）の算出スタイルを比較しました。幅393ライト・幅320ダークの各550状態、各約30万要素で**差分0件**です。この比較のあとに、第11版の修正（文字階層、44pt、新しい部品）を各セレクタの規則そのものへ反映しています（`scripts/v11/css-edition11-edits.mjs`）。

残っている点：
- 統合すると他の規則との優先順位が変わるため、同じセレクタの規則が2か所に分かれたままのものが68あります。
- 優先順位を保つために、本来の部品とは別のファイルに置いた規則が843あります（主に `base.css`）。ファイル名は部品を表しますが、分類は完全ではありません。
- 旧構成で詳細度を上げるために使われていた `#app` 付きのセレクタは、そのまま残しています。
- 比較はホバー・押下中・フォーカス中の状態、および巡回で到達しなかった画面を含みません。
